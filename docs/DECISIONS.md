# 결정 기록

**확정된 것만** 적는다. 검토 중이거나 제안 단계인 내용은 여기 오지 않는다.
여기 없는 것은 아직 결정되지 않은 것이다.

새 항목은 맨 위에 추가한다. 형식:

```
## YYYY-MM-DD · 제목
**확정:** 무엇을 하기로 했는가
**이유:** 왜 (다른 선택지를 버린 이유)
**영향:** 어떤 파일 / 어떤 동작
```

## 2026-09-03 · 물건 종별 필터는 드롭다운이 아니라 칩

**확정:** 종별·매각형태 필터를 고정 목록 칩으로 표시하고, 각 칩에 현재 조건의 건수를 붙인다.
대분류를 고르면 세분류 칩이 열리는 2단 구조.
**이유:** `<select>`는 화면에 로드된 물건에서 옵션을 만들어서 지도를 옮길 때마다 항목이 바뀌었다.
목록이 움직이면 고를 수가 없다. 칩 건수는 종별을 뺀 나머지 조건으로 세야 하나 고른 순간
나머지가 전부 0으로 보이지 않는다.
**영향:** `index.html`, `app.js` (renderCategoryFilters / matchesCategory), `styles.css` (.chip)

## 2026-09-03 · 물건 종별 분류는 `categories.js` 한 곳에서만

**확정:** 대분류 5 / 세분류 22 + 매각 형태를 `categories.js`에 정의하고, 서버와 브라우저가
같은 파일을 읽는다. 서버가 `categoryGroup` / `categorySub` / `categoryConfident` / `saleForm`을
실어 보내고 화면은 그 값만 읽는다.
**이유:** 분류 규칙이 어댑터·정규화·화면에 흩어져 있으면 세 곳이 서로 다른 답을 낸다.
판정 근거 우선순위(대괄호 목록구분 → 지목 → 법원 category leaf → 키워드)는 활성 물건
36,160건과 대조해서 정했다.
**영향:** `categories.js`, `lib/court.mjs`, `lib/onbid.mjs`, `lib/normalize.mjs`

## 2026-09-03 · 법원 `category`의 그룹 라벨은 정확히 일치할 때만 해석

**확정:** `상가,오피스텔,근린시설` 같은 검색 그룹 라벨은 완전 일치할 때만 그룹으로 읽고,
키워드 매칭 텍스트에는 `category`를 넣지 않는다.
**이유:** 부분 문자열로 훑으면 `상가,오피스텔,근린시설` 4,323건이 통째로 "오피스텔"이 된다.
**영향:** `categories.js`

## 2026-09-03 · 상가·오피스텔 모호 구간은 2단계로 확정

**확정:** 지하·1층이면 근린상가로 본다. 나머지는 `categoryConfident: false`로 두고
`/api/officetel-price` 조회가 성공하면 그때 확정한다. 카드에는 "추정 분류" 태그를 붙인다.
**이유:** 법원이 셋 중 무엇인지 공개하지 않는 유일한 진짜 모호 구간이다. 국세청 기준시가는
호실 단위로 용도를 들고 있어 PNU가 있으면 46%가 갈린다. 1층은 99%가 상가.
**영향:** `categories.js` (refineSubWithStandardPrice), `app.js` (refinedCategory)

## 2026-09-03 · 세션 작업 규칙을 `CLAUDE.md`에 둔다

**확정:** 여러 세션이 한 폴더를 공유하므로, 작업 규칙(시작 시 git 확인 / 종료 시 커밋 /
한 세션 한 주제 / 결정은 여기 기록)을 `CLAUDE.md`에 적어 모든 세션이 자동으로 읽게 한다.
**이유:** 규칙이 대화 안에만 있으면 세션 경계를 넘지 못한다. 사람이 매 세션 같은 말을 반복해야 했다.
**영향:** `CLAUDE.md`, `docs/DECISIONS.md`
