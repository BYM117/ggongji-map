## 2026-09-12 · 상세 패널은 그리드 칸이 아니라 오버레이다

**확정:** 상세 패널은 데스크톱·모바일 모두 **지도 위에 떠 있는 오버레이**다. 레이아웃에서
자리를 차지하지 않는다. 데스크톱은 오른쪽에서 밀려 들어오고(`position: absolute; right: 0`),
모바일은 아래에서 올라와 화면을 덮는다. 그리드 칸을 따로 잡아주지 않는다.

**이유:** 원래는 세 번째 그리드 칸이었다가 오버레이로 바꿨는데, 그 흔적이 여러 곳에 남아
같은 종류의 버그가 **세 번** 났다. 전부 "레이아웃을 오버레이로 바꿨는데 예전 전제가
남아 있던" 경우다.

1. `@media (max-width: 1240px)`에 세 번째 칸 `360px`이 남아 1041~1240px에서 오른쪽이
   통째로 비고 지도가 그만큼 좁았다(1200px에서 지도 480px, 빈 칸 360px).
2. `@media (max-width: 1040px)`의 `.detail-panel { overflow: visible }`이 남아, 고정
   오버레이가 된 뒤에도 스크롤이 없었다. 내용 1,162px 중 762px만 보이고 나머지는
   `app-shell`의 `overflow: hidden`에 잘렸다.
3. 목록 시트를 `transform: translateY`로 내리면서 높이는 `88dvh`로 뒀더니, 화면 밖으로
   나간 부분까지 안쪽 목록이 자기 높이로 계산해 끝까지 스크롤해도 마지막 항목이 안 보였다.

**영향:** `styles.css`의 `.app-shell` / `.detail-panel` / `.sidebar` 미디어쿼리 전부

**다음에 이 냄새가 나면 의심할 것:** 화면 한쪽이 이유 없이 비거나, 스크롤이 중간에서
막히거나, 내용이 잘려 보인다면 **문서처럼 흐르던 시절의 값이 남았는지** 먼저 본다.
구체적으로 `grid-template-columns`의 남는 칸, `overflow: visible`, `height: auto`,
`position: static`. 오버레이로 바꿀 때는 이 넷을 세트로 같이 고쳐야 한다.

**정리 완료:** `@media (max-width: 1040px)`에 남아 있던 `.app-shell` / `.sidebar` /
`.detail-panel`의 `overflow: visible` 세 줄은 지웠다(2026-09-12). 지우기 전에
375 / 1000 / 1040px × 시트 3단계 × 상세 열림·닫힘 × body 클래스 없는 상태까지
계산 속성 13종과 박스 좌표를 비교해 **차이 0**을 확인했다.
파일 뒤쪽 모바일 블록의 `overflow: hidden` / `overflow-y: auto`가 진짜 값이다.
**그쪽을 지우면 세 버그가 한꺼번에 되살아난다.**

## 2026-09-11 · 전국까지 줄이면 물건 대신 시·도별 개수만 받아온다

**확정:** 줌 8 이하(시·도 단위로 그리는 구간)에서는 개별 물건을 받지 않고
`/api/viewport-clusters`로 시·도별 개수만 받아 덩어리로 그린다. 왼쪽 패널은 물건 목록
대신 **지역별 물건 수**를 많은 순으로 보여주고, 누르면 줌 10으로 그 지역에 들어간다.
헤더는 총 개수만 찍고 공시가·입찰임박은 줄표로 둔다. 필터는 개수를 떼고 잠근다.
서버가 "시·군·구까지 나눠 봐야 한다"(needs_detail)고 하면 기존 경로로 내려간다.
**이유:** 전국 화면은 32,000건이라 업스트림에서 받아오는 데만 26초가 걸려 30초 제한에
걸려 죽었다(브라우저에서 4연속 504). 페이지를 병렬로 받게 고쳐도 크롤러 쪽이 못 따라와
여전히 실패했다 — 3만 건을 하나씩 받아온다는 것 자체가 틀린 방식이었다.
업스트림은 "이 조건에 몇 건인가"를 1KB · 0.3초에 답해주고 region 필터가 시·도·시군구까지
정확히 먹는다(실측: region=서울특별시 3,665건, region+화면경계도 같이 걸린다).
목록 자리에 "확대해 주세요"만 띄우는 안도 있었으나, 개수는 이미 손에 있으므로
어디에 물건이 많은지 보여주는 쪽이 빈 화면보다 쓸모 있다고 판단했다.
공시가·입찰임박을 0으로 찍지 않는 이유는 0이 "없다"로 읽히기 때문이다.
필터 개수를 떼는 이유는 화면은 "31,029개"인데 필터는 "전체 (0)"이라 서로 어긋나서다.
**영향:** `lib/geo.mjs`(`PROVINCE_EXTENTS` / `provincesInBounds`),
`lib/court.mjs`(`fetchCourtAuctionClusters`), `dev-server.mjs`(`/api/viewport-clusters`),
`app.js`(`state.regionSummary` / `loadRegionSummary` / `regionSummaryClusters` /
`renderRegionSummaryPanel` / `zoomToRegion` / `spreadOverlappingMarkers`), `styles.css`(`.region-row`)
**실측:** 전국 화면 30초 후 504 → 1.5초 · 819바이트. 합계 31,029개가 시·도별로 맞는다.
부산 줄을 누르면 줌 10으로 이동해 물건 7,163개를 받아오고 목록·필터가 정상 복귀한다.
**주의:** 시·도 중심을 제자리에 찍으면 수도권 셋과 세종·대전 라벨이 겹친다(세종↔대전 25px).
겹친 마커만 라벨 폭(78px)만큼 밀어 띄운다. 이 줌에서는 정확한 위치보다 읽히는 게 우선이다.
**미정:** 시·군·구별 개수 표를 만들면 수도권 화면(지금 6초)도 같은 방식으로 줄일 수 있다.

## 2026-09-10 · 지도 묶는 등급은 화면이 아니라 구역마다 따로 정한다

**확정:** 시·군·구로 쪼갤지는 시·도마다, 읍·면·동으로 쪼갤지는 시·군·구마다 따로 판단한다.
기준은 **그 구역이 지금 화면에서 차지하는 폭**이다. 화면의 45%(`ADMIN_SPLIT_SHARE`) 이상을
차지할 때만 쪼개고, 그보다 좁으면 통으로 둔다. 폭은 최소~최대가 아니라 **가운데 90%**로 잰다.
개별 물건으로 바뀌는 시점(줌 14)은 지금 그대로 둔다.
**이유:** 화면 전체에 등급 하나를 적용하니 서울 25개 구와 경기 31개 시가 같이 쪼개졌다.
서울은 30km 안에 몰려 있어 라벨이 겹쳐 뭉개지고 경기는 130km에 퍼져 있어 안 겹친다 —
등급이 같아도 화면에서 보이는 모습이 딴판이다. 수도권 화면 실측: 시·군·구 등급이면 마커 69개인데
그중 36개(서울 25 + 인천 11)가 구석에 몰렸다. 시·도 등급으로 통일하면 3개뿐이라 지도가 휑했다.
"마커 개수 상한"으로 정하는 안도 검토했으나 그 규칙은 이 화면에서 시·도(3개)를 골라 같은 문제였다.
최소~최대로 폭을 재던 초안은 옹진군 섬 때문에 인천이 60%로 잡혀 쪼개졌다. 가운데 90%로 바꾸니 23%가 됐다.
**영향:** `app.js`(`makeAdminClusters` 분해 → `buildAdminClusters` + `adminSpreadShare`,
`ADMIN_PARENT_LEVEL` / `ADMIN_SPLIT_SHARE`), `index.html`(캐시 버스터)
**실측:** 줌10 수도권 마커 38개(서울·인천 통으로, 경기 시 단위) / 줌12 서울시 39개(구 단위) /
줌14 개별 물건. 줌이 바뀌어도 마커 수가 38~39개로 유지된다.
**미정:** 45%가 적당한 값인지는 써 보고 정한다. 낮추면 잘게, 올리면 뭉뚱그려 보인다.

## 2026-09-09 · 왼쪽 필터는 드롭다운으로 통일하고, 정렬 선택은 없앤다

**확정:** 물건 종별(대분류 → 세부 종별)과 매각 형태를 칩에서 `<select>`로 되돌린다.
세부 종별은 대분류를 고른 뒤에만 나타나고, 선택은 하나씩만 한다(칩 시절의 세분류 다중 선택은 없앴다).
칩에 붙던 건수는 옵션 라벨에 그대로 남긴다 — `주거 (2,625)`.
지역 드롭다운은 시·도별 `<optgroup>`으로 묶고 그 안을 가나다순으로 고정한다.
공시가 범위 필터(손잡이 두 개)를 추가한다. 눈금은 `OFFICIAL_PRICE_STEPS`의 19단계.
정렬 드롭다운은 통째로 없애고, 목록은 공시기준 할인율 내림차순 한 가지로 고정한다.
**이유:** 칩은 건수를 눈으로 훑을 수 있어 좋았지만 대분류 6 + 세분류 최대 7 + 매각 형태 5가
늘 펼쳐져 있어 필터가 필요 이상으로 자리를 차지했고, 정작 봐야 할 목록이 그만큼 밀렸다.
지역은 로드된 물건에서 옵션을 만들다 보니 도착 순서대로 섞여 같은 시의 구가 흩어져 있었다.
정렬은 기본값이던 "추천 점수순"이 무엇으로 매겨진 순서인지 화면에서 설명할 방법이 없었다.
공시가 대비 얼마나 싼지가 이 도구의 유일한 축이므로 그 하나로 고정한다(`score`는 마커 등급에만 남는다).
공시가 범위는 한쪽이라도 좁히면 공시가 미확인 물건이 빠진다 — 금액으로 거르겠다고 한 이상
금액을 모르는 물건은 조건에 맞는지 판단할 방법이 없다. 양 끝에 있으면 아무것도 거르지 않는다.
**영향:** `index.html`(필터 섹션 전체), `app.js`(`state.filters`: `categorySubs` Set → `categorySub`
문자열, `sortBy` 제거, `officialMin`/`officialMax` 추가 / `renderCategoryFilters` / `populateFilters` /
`matchesOfficialRange` / `sortProperties` 고정), `styles.css`(칩 스타일 제거, `.field-head`, `.dual-range`)

## 2026-09-04 · 할인율에 색을 쓰지 않는다 (시안 D · 계량)

**확정:** 공시기준 대비 할인율은 항상 중립 먹빛으로 찍는다. 초록/빨강 어느 쪽으로도
칠하지 않는다. 판단 근거는 색이 아니라 형태가 낸다 — 잔존율은 게이지 막대 길이,
유찰은 도트 개수, 그리고 상세 최상단 판정 배너. 지도 마커의 점수별 색 등급도 같이 없앴다.
오렌지(`--signal #EE5A0E`)는 "지금 봐야 할 것"에만 쓴다: 입찰 임박, 선택 상태, 게이지 채움.
**이유:** 할인율이 클수록 초록이 진해지는 규칙이었는데, 정작 할인율 최상위 물건은
유찰 17회에 최저가율 2%인 특수물건이었다(2023타경4722). 화면에서 가장 좋은 딜로 보였다.
빨강으로 뒤집는 것도 답이 아니다 — "나쁜 물건"이라는 다른 오독을 만든다. 사실은
나쁜 게 아니라 **이 숫자를 그대로 믿으면 안 된다**는 것이고, 그건 색으로 말할 수 없다.
게이지 길이와 도트 개수는 색과 무관해 색각 이상 사용자에게도 같은 정보가 전달된다.
**영향:** `styles.css`(토큰 레이어 + 시안 D 컴포넌트 레이어), `app.js`
(`officialDiscountTone` 중립 고정 / `residualRatio` / `fillGauge` / `fillFailDots` /
`renderVerdict` / `markerColor` 단색화), `index.html`(카드 템플릿)
**주의:** 빗금(해칭)은 쓰지 않기로 했다. 잔여 구간은 평면 트랙으로 둔다.
`--muted`는 4.5:1 미만으로 내리지 말 것 — 한 번 3.33:1까지 내려가 AA를 깼다.

## 2026-09-04 · VWorld는 로컬에서도 운영 도메인으로 호출한다

**확정:** `.env`의 `VWORLD_API_DOMAIN`을 `https://ggongji-map.vercel.app`으로 둔다.
`127.0.0.1`을 쓰지 않는다. 배포 코드도 `VERCEL_URL`이 아니라
`VERCEL_PROJECT_PRODUCTION_URL`을 먼저 본다.
**이유:** VWorld는 등록된 도메인에서 온 호출만 받아준다. `domain`은 우리가 보내는
파라미터라 어디서 호출하든 값만 맞으면 된다. `VERCEL_URL`은 배포마다 바뀌는 일회성
주소(`ggongji-map-abc123.vercel.app`)여서 등록 도메인과 영영 일치하지 않았다.
**영향:** `lib/vworld.mjs`(`vworldDomain`), `.env`
**주의:** VWorld 호출은 간헐적으로 끊긴다(실측 10회 중 3회). `fetchJsonRetry`가 3회까지
재시도하고, 그래도 실패하면 `withUpstreamFallback`이 503과 안내 문구를 값으로 돌려준다.
이 두 겹을 걷어내면 공시가 칸이 통째로 비는 500이 다시 새어나온다.

## 2026-09-04 · 세션 엉킴의 1차 방어선은 워크트리가 아니라 커밋 규칙

**확정:** 기본값은 원본 폴더에서 그대로 작업하는 것이다. 워크트리 스크립트
(`scripts/새작업.sh` / `작업끝.sh` / `작업목록.sh`)는 남겨두되, **두 세션이 같은 파일을
동시에 고치는 게 확인된 경우에만** 세션이 직접 꺼내 쓴다. 사용자는 CLI를 쓰지 않는다.
**이유:** 실제로 발생한 사고 두 건(커밋 없이 떠 있던 420줄, `.tag.good` CSS 회귀)은 둘 다
폴더를 나눴어도 똑같이 일어났을 종류였다. 원인은 "저장 안 하고 세션을 떠남"과 "한 파일
안에서 잘못된 위치에 규칙 삽입"이다. 워크트리는 이걸 막지 못한다.
또 사용자는 Claude 데스크톱 앱에서 세션을 나눠 쓰므로, 새 폴더를 쓰려면 세션의 작업
디렉터리를 옮기는 수작업이 매번 필요하다. 현재 규모에서는 얻는 것보다 번거로움이 크다.
**영향:** `CLAUDE.md`(선택 사항으로 표시), `scripts/*.sh`(유지)
**주의:** `.env`는 git이 관리하지 않아 워크트리에 생기지 않는다. 스크립트가 심볼릭 링크로
이어주므로 키는 원본 한 곳에서만 관리된다.

## 2026-09-03 · 물건 종별 필터는 드롭다운이 아니라 칩

**확정:** 종별·매각형태 필터를 고정 목록 칩으로 표시하고, 각 칩에 현재 조건의 건수를 붙인다.
대분류를 고르면 세분류 칩이 열리는 2단 구조.
**이유:** `<select>`는 화면에 로드된 물건에서 옵션을 만들어서 지도를 옮길 때마다 항목이 바뀌었다.
목록이 움직이면 고를 수가 없다. 칩 건수는 종별을 뺀 나머지 조건으로 세야 하나 고른 순간

## 2026-09-09 · 분류 근거는 `address.detail` 우선, 주용도는 국세청 다음

**확정:** (1) 대괄호 파싱은 `property.address.detail`을 1순위로 쓴다. (2) 목록구분은 대괄호 안

**이유:** `detail`은 수집기가 유지하는 계약이라 원문 표기가 바뀌어도 안전하다(실측 32,033건 전부
`raw` 대괄호와 일치). 첫 단어만 보면 `[현황:○○]`이 앞에 붙거나 대괄호가 중첩된 3건을 놓쳤다.
주용도는 "필지 대표 건물" 값이라 주상복합에서 어긋난다 — 수집기가 연면적 최대 동을 고르기 때문.
국세청은 호실 단위라 항상 우선이다.
**실측:** 주용도가 오면 미확정 표본 150건 중 130건(87%) 해소. 필드 도착 전에도 국세청 조회만으로
미확정 2,982 → 1,658건(5.2%).

6MB씩 서버리스 함수를 통과시킬 이유가 없다. url을 검사 없이 fetch하면 SSRF 통로가 된다.
