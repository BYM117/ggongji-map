# 배포된 화면에 공매가 0건으로 뜬다

**상태:** 원인 좁혀짐 · 미착수 · 다른 세션에서 처리 예정
**발견:** 2026-09-13 (공매 상세 배포 직후 확인 중에)
**갱신:** 2026-09-13 (2차) — 앞선 두 판의 결론이 모두 근거가 부실해서 고쳤다.
확인된 사실만 남기고, 추측은 "남은 후보"로 내렸다.
**영향 범위:** `lib/vworld.mjs` 또는 Vercel 환경 설정. 코드가 아니라 환경 쪽일 가능성이 크다.

---

## 한 줄로

로컬에서는 같은 화면에 공매가 25건 뜨는데 **배포된 화면에서는 0건**이다.
공매 물건은 좌표가 없어 주소로 구해야 하는데, **VWorld가 Vercel에서만 502를 준다.**

이것 때문에 온비드 상세 기능이 배포는 됐지만 화면에서는 아직 볼 수 없다.

---

## 증거

프로덕션 `viewport-properties` 진단 응답:

```
regionSource:     "province_fallback"     ← 시군구를 못 구해 시도 단위로 떨어졌다
regionError:      "502 Bad Gateway"       ← VWorld 역지오코딩 실패
scannedRows:      5032
uniqueCount:      558
geocodeAttempts:  8
geocodeSuccesses: 0                       ← 좌표를 하나도 못 구했다
returnedCount:    0
```

558건을 추려놓고 좌표가 없어 전부 버린다.

## 확인한 것 / 아닌 것으로 밝혀진 것

같은 키로 개발 PC에서 VWorld를 직접 부르면 **정상(HTTP 200, status OK)**이다.

도메인 제한도 아니다. `domain` 파라미터를 네 가지로 바꿔가며 불러도 전부 `OK`였다.

```
(도메인 없음)                            200 OK
http://127.0.0.1:4173                   200 OK
https://ggongji-map.vercel.app          200 OK
https://ggongji-map-abc123.vercel.app   200 OK
```

`vworldDomain()`(`lib/vworld.mjs:463`)도 이미 배포마다 바뀌는 `VERCEL_URL`보다
고정 주소인 `VERCEL_PROJECT_PRODUCTION_URL`을 먼저 쓰도록 돼 있다.

### 배포에서 주소→좌표가 실패하는 것은 확인됐다

`/api/geocode`로 같은 주소를 로컬과 배포에 각각 물어본 결과다. 이 경로는 VWorld
주소검색(`/req/search`)을 그대로 쓴다.

```
로컬   HTTP 200  found: true   lat 37.5596  lng 126.9112  pnu 1144012500100270000
배포   HTTP 200  found: false  (좌표 없음)
```

같은 주소, 같은 코드, 같은 키인데 배포에서만 못 찾는다. 이것이 공매 0건의 직접 원인이다.

### 아닌 것으로 확인된 것들

- **키가 빠진 게 아니다.** `fetchGeocode()`(`lib/vworld.mjs:310`)는 키가 없으면
  `ok:false, error:"missing_key"`를 돌려준다. 배포는 `ok:true, found:false`를 준다.
  **즉 Vercel에 키는 들어 있다.**
- **등록 URL 문제가 아니다.** VWorld 인증키의 서비스URL에 `https://ggongji-map.vercel.app/`가
  등록돼 있고 지오코더·검색 API도 활성화돼 있다(2026-09-13 사용자 확인).
- **코드 문제가 아니다.** 같은 코드가 로컬에서는 좌표를 찾는다.

### 앞선 판에서 틀렸던 것 — 근거 없이 적은 문장

첫 판은 "Vercel에서 VWorld로 나가는 경로 자체가 막혔다"고 단정했다. 둘째 판은 그것을
뒤집으며 "개별공시지가(`/ned/data`)는 배포에서 정상"이라고 적었다. **둘 다 근거가 부실했다.**

`land-price`가 배포에서 `ok:true`를 준 것을 "정상"으로 읽었는데, **값은 `null`이었고
로컬에서도 똑같이 `null`이다.** 애초에 VWorld가 값을 주는지 아닌지를 가릴 수 없는 요청이었다.
그것으로 "이쪽 계열은 살아 있다"고 말할 수 없다.

**교훈: `ok:true`는 성공이 아니다. 값이 실제로 들어 있는지를 봐야 한다.**
그리고 한 번 잰 값으로 결론 내리지 말 것 — 같은 `land-price`가 503과 200을 오갔다.

## 지금 남은 것

키도 도메인도 코드도 아니라면, 남은 차이는 **요청이 어디서 나가느냐**뿐이다.
개발 PC에서 나가면 되고 Vercel에서 나가면 안 된다.

다만 이것도 아직 **확인이 아니라 남은 후보**다. 밖에서 확인할 수 있는 수단이 떨어졌다.

다음 세션이 해볼 만한 것:

1. **배포 환경에서 VWorld 응답 원문을 그대로 찍어 보기.** 지금은 `regionError`가 앞부분만
   잘려 저장돼 무슨 말인지 알 수 없다(`<html><body><h1>502 Bad Gateway</h1>…`).
   VWorld가 거부 사유를 본문에 적어 보내는지부터 봐야 한다. 이게 제일 확실하다.
2. 그래도 원인이 안 잡히면 **요청 시점에 좌표를 구하는 방식 자체를 접는다.**
   온비드 물건 좌표를 미리 구해 저장해 두고 화면은 그걸 읽기만 하게 한다.
   VWorld가 배포에서 왜 막는지와 무관하게 문제가 사라지고, 25초 걸리던 응답도 같이 없어진다.
   **현실적으로는 이쪽이 답일 가능성이 높다.**

`lib/vworld.mjs`를 고치는 것으로 시작하지 말 것. 거기엔 고칠 게 없다.

## 곁가지로 보이는 것

프로덕션 공매 뷰포트 응답이 **25초** 걸린다(30초 제한에 가깝다).
좌표 조회가 실패로 끝나기까지 매달리는 시간이 그대로 쌓이는 것으로 보인다.
1번이 풀리면 같이 사라질 수 있으니, 이것만 따로 손대지 말 것.

`lib/onbid.mjs` 상단 주석이 이 상황을 이미 예상하고 있다 —
"좌표 조회가 통째로 막히는 일이 실제로 있다(배포 환경의 VWorld 장애)".
그때를 위한 fallback이 도는 중인데, 지금은 fallback조차 좌표를 못 구해 0건이 된다.
