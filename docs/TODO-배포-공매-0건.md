# 배포된 화면에 공매가 0건으로 뜬다

**상태:** 원인 좁혀짐 · 미착수 · 다른 세션에서 처리 예정
**발견:** 2026-09-13 (공매 상세 배포 직후 확인 중에)
**갱신:** 2026-09-13 — 첫 판의 결론("VWorld 경로 전체가 막혔다")이 틀려서 고쳤다.
막힌 것은 `/req/*` 계열뿐이고 NED 데이터 API는 정상이다.
**영향 범위:** `lib/vworld.mjs` 또는 Vercel 환경 설정. 코드가 아니라 환경 쪽일 가능성이 크다.

---

## 한 줄로

로컬에서는 같은 화면에 공매가 25건 뜨는데 **배포된 화면에서는 0건**이다.
공매 물건은 좌표가 없어 주소로 구해야 하는데, **VWorld가 Vercel에서만 502를 준다.**

이것 때문에 온비드 상세 기능이 배포는 됐지만 화면에서는 아직 볼 수 없다.

---

## 증거

프로덕션 `viewport-properties` 진단 응답:

```
regionSource:     "province_fallback"     ← 시군구를 못 구해 시도 단위로 떨어졌다
regionError:      "502 Bad Gateway"       ← VWorld 역지오코딩 실패
scannedRows:      5032
uniqueCount:      558
geocodeAttempts:  8
geocodeSuccesses: 0                       ← 좌표를 하나도 못 구했다
returnedCount:    0
```

558건을 추려놓고 좌표가 없어 전부 버린다.

## 확인한 것 / 아닌 것으로 밝혀진 것

같은 키로 개발 PC에서 VWorld를 직접 부르면 **정상(HTTP 200, status OK)**이다.

도메인 제한도 아니다. `domain` 파라미터를 네 가지로 바꿔가며 불러도 전부 `OK`였다.

```
(도메인 없음)                            200 OK
http://127.0.0.1:4173                   200 OK
https://ggongji-map.vercel.app          200 OK
https://ggongji-map-abc123.vercel.app   200 OK
```

`vworldDomain()`(`lib/vworld.mjs:463`)도 이미 배포마다 바뀌는 `VERCEL_URL`보다
고정 주소인 `VERCEL_PROJECT_PRODUCTION_URL`을 먼저 쓰도록 돼 있다.

### 막힌 것은 VWorld 전체가 아니라 `/req/*` 계열뿐이다

**이 문서의 첫 판(2026-09-13)은 "Vercel에서 VWorld로 나가는 경로 자체가 막혀 있다"고
적었는데, 그것은 틀렸다.** 프로덕션에서 서비스별로 나눠 재보니 갈린다.

| VWorld 주소 | 쓰는 곳 | `lib/vworld.mjs` | 프로덕션 |
|---|---|---|---|
| `api.vworld.kr/ned/data/getIndvdLandPriceAttr` | 개별공시지가 | 47 | **200 정상** |
| `api.vworld.kr/req/address` | 역지오코딩(시군구) | 354 | **502** |
| `api.vworld.kr/req/search` | 주소→좌표 | 420 | **502** |

같은 배포, 같은 키, 같은 나가는 IP인데 한쪽은 되고 한쪽은 안 된다.
**그러므로 네트워크가 통째로 막힌 것도, 키가 죽은 것도 아니다. 오픈API(`/req/*`) 계열만
거부당하고 있다.** NED 데이터 API는 인증 방식이 달라서 영향을 받지 않는 것으로 보인다.

주의: 처음 쟀을 때 `land-price`가 503이 나와 "이것도 막혔다"고 볼 뻔했다.
**다시 재니 200이었다. 일시적인 값에 결론을 걸지 말 것.** 이 문서의 첫 판이 그렇게 틀렸다.

## 다음 세션이 먼저 볼 것

1. **VWorld 인증키의 "사용 URL"에 배포 도메인이 등록돼 있는지.** 오픈API(`/req/*`)는
   등록된 도메인을 따지고 NED 데이터 API는 안 따진다면, 지금 갈리는 모양이 정확히 설명된다.
   `https://ggongji-map.vercel.app`이 등록돼 있는지 VWorld 사이트에서 확인하는 것이 가장 싸다.
2. **Vercel 환경변수에 `VWORLD_API_DOMAIN`이 들어가 있는지.** `.env`를 그대로 복사해
   `http://127.0.0.1:4173`이 박혀 있으면 그 값이 최우선으로 쓰인다(`lib/vworld.mjs:464`).
   다만 공시지가 호출도 같은 값을 함께 보내는데 그쪽은 통과하므로, 이것만으로는 설명이 안 된다.
   1번을 확인한 뒤에 볼 것.
3. IP 차단은 순위를 내렸다. 같은 Vercel에서 나가는 NED 호출이 멀쩡하기 때문이다.

어느 쪽이든 코드 문제는 아니다. **`lib/vworld.mjs`를 고치는 것으로 시작하지 말 것.**

## 곁가지로 보이는 것

프로덕션 공매 뷰포트 응답이 **25초** 걸린다(30초 제한에 가깝다).
좌표 조회가 실패로 끝나기까지 매달리는 시간이 그대로 쌓이는 것으로 보인다.
1번이 풀리면 같이 사라질 수 있으니, 이것만 따로 손대지 말 것.

`lib/onbid.mjs` 상단 주석이 이 상황을 이미 예상하고 있다 —
"좌표 조회가 통째로 막히는 일이 실제로 있다(배포 환경의 VWorld 장애)".
그때를 위한 fallback이 도는 중인데, 지금은 fallback조차 좌표를 못 구해 0건이 된다.
