## 1. 이 도구가 푸는 문제

**한 줄:** 경공매 물건이 *공시가격 기준으로* 싼지를 지도 위에서 판단하게 한다.

축이 하나뿐이라는 것이 이 도구의 성격을 거의 다 정한다.

- 정렬은 **공시기준 할인율 내림차순 하나로 고정**돼 있다. 정렬 드롭다운을 일부러 없앴다
  (`DECISIONS.md 2026-09-09`). "추천 점수순"이 무엇으로 매겨진 순서인지 화면에서
  설명할 방법이 없었기 때문이다.
- `score`는 남아 있지만 **마커 등급에만** 쓴다. 목록 순서에는 관여하지 않는다.
- 할인율에 **색을 쓰지 않는다** (`DECISIONS.md 2026-09-04`). 할인율 1등이 유찰 17회짜리
  특수물건이었고, 화면에서 가장 좋은 딜로 보였다. 판단 근거는 색이 아니라 형태가 낸다 —
  게이지 길이, 유찰 도트, 상세 최상단 판정 배너.

> **여기서 파생되는 원칙:** 숫자가 커 보이는 이유를 같이 보여주지 않으면 그 숫자는 거짓말이다.
> 새 지표를 추가할 때 이 기준을 통과하는지 먼저 물어볼 것.

## 3. 지금 서 있는 자리

### 데이터가 흐르는 길

```
브라우저 (app.js, 클래식 스크립트 — 빌드 도구 없음)
   │
   │  줌 ≤ 8   → /api/viewport-clusters   ── 시·도별 "개수"만 (물건 없음)
   │  줌 ≥ 9   → /api/viewport-properties ── 화면 안 물건
   │  검색     → /api/search-properties   ── 전국, 업스트림에 위임
   │  클릭     → /api/court-auction-detail  또는  /api/onbid-detail
   │  보강     → /api/geocode · land-price · housing-price
   │             officetel-price · seoul-deals · parcel-boundary
   ▼
dev-server.mjs  (로컬 = 서버, Vercel = api/[...path].mjs 가 재사용)
   │
   ├─ lib/court.mjs        → 원격 법원 크롤러 API   (COURT_AUCTION_API_URL)
   ├─ lib/onbid.mjs        → 온비드 OpenAPI          (ONBID_SERVICE_KEY)
   ├─ lib/vworld.mjs       → VWorld 공시가·지오코딩  (VWORLD_API_KEY)
   ├─ lib/seoul.mjs        → 서울 열린데이터          (SEOUL_REAL_ESTATE_API_KEY)
   ├─ lib/officetel.mjs    → 로컬 gzip 인덱스        (data/officetel-prices/*, 키 불필요)
   └─ lib/official-prices.mjs → 오프라인 사전계산 사이드카 (data/official-prices.json.gz)
                                 ↑ scripts/enrich-official-prices.mjs 가 만든다
```

**중요:** 법원 크롤러는 **원격 API**다. 이 컴퓨터의 `~/Documents`에 있는
`auction_crawler_runtime/`, `경매물건 크롤링*` 폴더는 **전부 마이그레이션 이전 유물**이고
현행 코드가 아니다. 열지 말 것 (`CLAUDE.md`, `DECISIONS.md 2026-09-12`).
크롤러가 무엇을 주는지 알아야 하면 `lib/court-detail.mjs`의 `normalizeDetail()`을 본다.

## 4. 이 프로젝트에서 반복해서 난 실패 — 여섯 가지 냄새

git 로그가 증언하는 패턴이다. **새 코드를 짤 때 이 여섯 개를 먼저 통과시켜라.**
지금까지 난 사고의 대부분이 여기 들어간다.

### ① 전부 받아놓고 메모리에서 거른다

상대가 서버에서 걸러줄 수 있는데도 전체를 긁어 와서 우리가 거른다.
**여섯 번 났다**(위 3단계 표). 전국 54,849건을 앞에서부터 1,000건 긁던 것,
실거래 32만 건을 훑던 것, 페이지를 한 장씩 줄 세워 받던 것.

> **묻기:** 이 API가 서버에서 걸러주는 조건이 정말 없는가? 문서 말고 **실제로 호출해서** 확인했는가?

### ② 캐시 키가 구분해야 할 것을 구분하지 않는다

`6427df4`("서울 밖이 물건 없음")가 정확히 이거였다.
그리고 **2026-09-13 점검에서 같은 실수가 같은 파일에 또 있는 것을 찾았다**
(`TODO-점검-2026-09-13.md` A-2: `q`·`region`이 캐시 키에 없다).

> **묻기:** 이 캐시가 돌려주는 값을 바꿀 수 있는 입력을 **전부** 키에 넣었는가?
> 필터 목록과 키 목록이 **다른 곳 두 군데**에 적혀 있지는 않은가?

### ③ 전제가 바뀌었는데 옛 전제가 남는다

상세 패널을 그리드 칸 → 오버레이로 바꿨는데 그 흔적이 여기저기 남아
**같은 종류의 버그가 세 번** 났다 (`DECISIONS.md 2026-09-12`에 전말이 적혀 있다).

> **묻기:** 이 전제를 바꾸면 같이 바뀌어야 할 값이 어디에 또 있나?
> CSS라면 `grid-template-columns`의 남는 칸 / `overflow: visible` / `height: auto` /
> `position: static` **넷을 세트로** 확인한다.

### ④ 같은 규칙이 두 곳에 생긴다

분류 규칙이 세 곳에 흩어져 세 가지 답을 내던 것을 `categories.js`로 모았다(`dac3478`).
그런데 **좌표 테이블은 여전히 세 파일 네 군데에 있다**
(`TODO-점검-2026-09-13.md` D절). `ADMIN_SPLIT_SHARE`도 두 곳인데,
주석 세 곳이 "같은 기준"이라고 적혀 있지만 **사실이 아니다** — 재는 대상이 다르다.

> **묻기:** 이 값/규칙의 주인이 누구인가? 주석에 "○○와 같다"고 쓰고 싶어지면
> **그건 복사하고 있다는 신호다.** 진짜로 같은지 확인하거나, 한 곳에서 가져다 쓰게 만들어라.

### ⑤ 실패를 성공으로 읽는다

배포 공매 0건 문서가 **두 번** 이것 때문에 틀렸다.
`land-price`가 `ok:true`를 준 것을 "정상"으로 읽었는데 값은 `null`이었고,
로컬에서도 똑같이 `null`이었다 (`a979f1c`, `f578c4e`).

코드에도 같은 게 있다 — `fetchVworldPoint`가 "주소가 없다"와 "VWorld가 죽었다"를
**똑같이 `null`로** 돌려주고, 그걸 `found:false`로 캐시한다
(`TODO-점검-2026-09-13.md` C-2).

> **묻기:** `ok:true`가 아니라 **값이 실제로 들어 있는지** 봤는가?
> "못 찾음"과 "못 물어봄"을 코드가 구분하는가?
> 한 번 잰 값으로 결론 내리지 않았는가? (같은 `land-price`가 503과 200을 오갔다)

### ⑥ 출처를 보지 않고 한쪽으로 다 보낸다

공매 물건에 법원 상세를 물어보고 있었다(`29d578c`, `2418bb1`).
경매와 공매는 **물건번호 생김새부터 다르다.**

> **묻기:** 이 물건이 법원 것인지 온비드 것인지 여기서 갈라야 하는가?
> `sourceKind(item)`이 그 판정의 단일 진입점이다(`app.js:2653`).

### ⑦ 낡은 사본이 방금 갱신한 것을 덮어쓴다

2026-09-13 점검에서 찾았다(`TODO-점검-2026-09-13.md` G-1).
`hydrateReferenceData`가 여러 단계를 이어 돌리는데, 각 단계가 `properties`를 **통째로
교체**한다. 앞 단계가 갱신한 뒤 뒤 단계에 **갱신 전 배열**을 넘기면 그 값이 지워진다.
실측으로 공시가격 19건 중 13건이 사라졌고, 다음 하이드레이션이 다시 조회해
요청의 24%가 낭비되고 있었다.

무서운 점은 **코드가 이미 이 함정을 한 번 피했다**는 것이다. 같은 함수에서
`hydratePnu` 다음에는 `refreshTargets`로 최신 객체를 다시 집어온다 — 주석까지 붙어 있다.
**바로 다음 줄에서 같은 처리가 필요했는데 빠졌다.**

> **묻기:** 이 단계가 쓰는 배열은 앞 단계가 갱신하기 **전**에 만든 것인가?
> `{...item, 새필드}` 로 객체를 통째로 만들어 넣고 있다면, 그 `item`이 최신인지 확인했는가?
> 필드만 병합할 수는 없는가?

## 5. 앞으로

### 이미 확정된 방향 (`DECISIONS.md` 근거)

- **분류는 `categories.js` 한 곳에서만.** 서버가 `categoryGroup`/`categorySub`/
  `categoryConfident`/`saleForm`을 실어 보내고 화면은 그 값만 읽는다.
- **미확정 종별은 서버가 내보내기 전에 확정한다.** 화면에서만 확정하면 칩 건수가
  처음엔 틀린 값으로 보였다가 움직인다.
- **넓은 화면은 개별 물건을 받지 않는다.** 시·도별 개수만 받아 덩어리로 그린다.
- **스냅샷 모드로 되돌아가지 않는다.** 빨라 보이지만 0건이다.
- **캐시 유효시간을 늘려 숫자를 좋게 만들지 않는다.** 경매는 최저가와 기일이 계속 바뀐다.
  오래된 값이 최신인 척 뜨는 것이 느린 것보다 나쁘다.
- **push는 매번 사용자 허락을 받는다.** push = 배포다 (`CLAUDE.md` 규칙 3).

## 6. 새 세션이 처음 30분에 할 것

```bash
git status && git log --oneline -5      # CLAUDE.md 규칙 1 — 남의 변경 위에 덮어쓰지 않는다
```

그다음 **이 순서로** 읽는다.

1. `CLAUDE.md` — 작업 규칙. 특히 **push는 매번 물어본다.**
2. 이 문서 4절(**여섯 가지 냄새**) — 지금 하려는 일이 여기 걸리는지 먼저 본다.
3. 건드릴 주제의 `docs/TODO-*.md`
4. `docs/DECISIONS.md`에서 그 파일이 언급된 항목

그리고 기억할 것:

- **서버는 Bash로 띄우지 않는다.** preview 도구와 `.claude/launch.json`을 쓴다
  (`ggongji` 4173 / `ggongji-4174` 4174).
- **⚠️ 화면·지도를 확인하려면 4173이어야 한다.** 4174에서는 네이버 지도 클라이언트 ID가
  막혀 지도가 안 뜬다(2026-09-13 실측, `TODO-점검-2026-09-13.md` G-5).
  `DECISIONS.md`에는 "포트만 다르고 하는 일은 같다"고 적혀 있지만 **화면은 같지 않다.**
  4174는 API·서버 작업에만 쓴다.
- **`app.js`와 `styles.css`를 건드리기 전에 `git status`.** 세션 충돌이 제일 잦은 두 파일이다.
- **`styles.css`는 같은 셀렉터가 상단과 미디어쿼리에 각각 있다.**
  선택자 목록 **중간에 끼워 넣지 말 것** — 그것 때문에 `.tag.good` 회귀가 났다(`a849868`).

  안 올려서 화면이 안 바뀐 적이 있다(`968bab5`).

  주인 없는 420줄이 생긴 적이 있다.
